# MathCups 数学群岛：语义规范 v1

本图把有独立来源的数学概念、对象、定理、方法、问题组织为岛屿，把有明确含义的关系组织为航线。它是可核查的知识组织与研究导航层；二维邻近、百科互链和数学可迁移性是三个不同量。

## 1. 岛屿的计数单位

一个岛屿是一份来源中具有稳定标识的数学知识条目。相同来源的重定向、别名、大小写或 Unicode 规范化差异不增加计数。人物、机构、书目、年表、索引、分类页和空占位页不能作为数学概念岛计数。证明条目、例子和练习如果保留，必须标明单独的内容类型，不能冒充不同概念。

跨来源同名不自动等同；同一名称可能指不同对象，不同名称也可能同义。合并须保留原始 ID、来源标题、别名和合并理由。超过 10,000 是经规则去重后的节点数；不表示这些条目已逐一经过数学家语义审查，也不表示数学知识已穷尽。未能确定岛型时用 `unclassified`，不能批量猜测为 `theorem`。

建议节点字段：`id`, `title`, `aliases`, `kind`, `domains`, `sources`, `source_ids`, `deduplication`, `typed_annotations`, `review_status`。岛型可取 `concept/object/theorem/method/problem/proof/example/unclassified`。领域允许多值；布局用的单一颜色不改变领域的多值语义。

实现可以保留来源的细类型，例如 `result/corollary/axiom/conjecture/theory/property/tool/research_program/correspondence/field/framework`；不要为了满足较小枚举而抹掉原始 `source_kind`。这些是来源内容分型，不等于 MathCups 的工具功能类型。当前首版数据以 `label` 表示标题，以 `source_url/source_id` 和源级清单连接来源，以 `domain/domain_code` 给出单一的制图归组；它还不是每岛完整多域、完整工具契约的人工形式化。独立的来源类型与未赋值的 MathCups 类型字段应同时保留。

## 2. 航线语义和证据

| 关系类型 | 含义 | 不能由此推出 |
| --- | --- | --- |
| `encyclopedic_link` | 来源 A 的正文或关系字段明确指向 B | A 的证明依赖 B；B 适用于 A |
| `classification` | 一个来源将条目分入一个类别 | 类别成员两两存在数学转换 |
| `equivalence` | 在给定对象和公理范围内有双向对应 | 任意扩大对象范围仍成立 |
| `representation` | 用另一种对象表达问题 | 无损、可逆或可计算，除非分别证明 |
| `reduction` | 在注明方向与复杂度范围内归约 | 反向归约、算法效率自动保持 |
| `construction` | 一种数学输入构造另一种对象 | 任意输入都满足构造前提 |
| `bound_transfer` | 某不变量或估计控制另一个量 | 等号成立或最优 |
| `invariant_identity` | 在给定范围内两个不变量满足恒等式 | 原对象可逆对应或可以被该不变量完全分类 |
| `proof_dependency` | 指定证明的一个步骤引用另一定理 | 所有证明都依赖该结果 |
| `candidate_bridge` | 由明确机制产生、尚待验证的迁移提议 | 新定理、独立发现或新颖性 |

边至少包含 `id/source/target/relation/status/evidence`。数学桥另包含 `mechanism/assumptions/conclusion/direction/limitations`。证据状态分别存储：来源是否可定位、相关段落是否读过、数学陈述是否审阅、是否有形式证明；不要压成一个无校准的“可信度分数”。`known_in_literature` 只是已有文献的陈述，绝不等于此图构建者重新证明。

无证据的语义相似边与共同分类边，不能混入已知数学桥或百科显式边。聚合边的 `weight` 必须注明是条目连接数、相似度还是人工权重，不能写成“定理强度”。

## 3. 二维图的解释

坐标另存 `x/y/layout_version/layout_method/seed`。坐标单位是布局单位；它们不表示难度、重要性、数学逻辑距离、知识的时间顺序或证明成本。分离的连通分量也可能在现实数学中有大量联系，只是所选来源没有记录。

万级总览采用区域与分层标签；详细索引保存所有岛屿。总览隐藏某些边必须说明筛选规则和总量。压缩二维图不可保留全部高维邻接，故检索、邻接表和最短路径需要直接基于原图；不能沿图上视觉最短距离推理。路径的边类型必须随结果显示，百科互链路径只作为阅读路线。

## 4. 与 MathCups 两层工具分型对接

第一层记录工具产生了什么：例如新表示、对象、结构、不变量、估计、算法、证明机制。第二层记录发现动作：例如转译、反例驱动修正、类比移植、目标重构、组合、局部至整体。这里仅给字段语义；旧 MathCups 注册表未在当前工作区恢复，不能新造 K/M/D 编号并声称兼容。

`typed_annotations` 可以包含 `artifact_type`、`discovery_action_type` 两个独立的渐近标签区间，各自为 `registry_version/must/may/open/evidence_refs/reviewer`。无逐条审查时默认 `must: [], may: [], open: true`。`must` 是有证据支持的下界；当 `open=false` 时 `may` 是允许上界，当 `open=true` 时 `may` 只是候选提示，允许的上界仍是整个固定注册表。

对于固定标签全集 U，解释为 γ(L,H)={S⊆U | L⊆S⊆H}。精化须满足 L_old⊆L_new 且 H_new⊆H_old。加入一个标签猜测不必然是精化，区间缩小不保证标签为真，历史报道不能当作心理过程的事实。更换注册表时必须显式迁移，不能与同一注册表内的精化混为一谈。

数学桥的条件也是结构化的待证义务：对象范围、局部假设、构造步骤、输出、失效边界分别记录。只有本航线自己的条件或显式继承的条件可用；不能借相邻航线的前提。已知理论的出现年代与发现过程的证据类型另存，不能由数学联系反推历史因果。

## 5. 从地图到可执行研究

研究请求应输出具体的迁移契约：源工具、目标问题、保留结构、丢失结构、缺失条件、可证伪的小边界、最终需证明的通用命题。候选可由共同不变量、同一范畴中的表示、互补估计或不同领域的同构结构产生；发现候选后须检索先例，避免把百科里未连边当作学术新颖性。

一个真实闭环是：候选桥 → 条件对齐 → 推导或反例 → 修订工具契约 → 独立核查 → 文献或形式证据登记。失败结果和反例同样形成可复用的边界知识。地图的首版不宣称自动完成上述研究过程。
